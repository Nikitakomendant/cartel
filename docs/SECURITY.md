# Захист сайту CARTEL

Що вбудовано і від чого захищає. Кожен пункт перевіряється автотестом `tests/security.test.js` або `tests/e2e_acceptance.py`.

## Веб-атаки
| Загроза | Захист |
|---|---|
| XSS (впровадження скриптів) | Автоекранування всіх шаблонів; rich text проходить білий список тегів (sanitize-html) при збереженні і при виводі; посилання — лише https/mailto/tel або відносні без лапок і тегів; Content-Security-Policy з одноразовим nonce для кожного скрипта, `object-src 'none'`, `base-uri 'self'`. |
| CSRF | Токен сесії на кожну дію в CMS + перевірка Origin; cookie `SameSite=Lax`. |
| SQL-інʼєкції | Лише підготовлені запити (better-sqlite3), жодної конкатенації. |
| Clickjacking | `frame-ancestors 'none'`, `X-Frame-Options: DENY`. |
| Open redirect | Параметр `next` після входу приймає лише адреси CMS. |
| Підміна Host | `ALLOWED_HOSTS` у production. |
| MIME-sniffing, витоки | `nosniff`, `Referrer-Policy`, `Permissions-Policy`, без `X-Powered-By`, HSTS 2 роки в production. |

## Доступ до CMS
- Паролі: scrypt (N=32768) із сіллю, мінімум 10 символів, літери + цифри, заборона простих.
- Перебір: 10 спроб входу / 15 хв з одного IP + блокування акаунта на 15 хв після 5 помилок. Однаковий час відповіді для існуючих і неіснуючих email (не можна вгадати логіни).
- 2FA (TOTP, Google Authenticator) для будь-якого користувача.
- Сесії зберігаються на сервері (у cookie — лише випадковий токен, у базі — його хеш), `HttpOnly`, `Secure`, префікс `__Host-`; тайм-аут бездіяльності 2 год, максимум 12 год; нова сесія після входу і зміни пароля.
- Ролі: HR не бачить контент і налаштування; маркетинг не бачить відгуків кандидатів і користувачів.
- Адресу CMS можна змінити (`ADMIN_PATH`), вона закрита від індексації.
- Журнал дій: входи, публікації, видалення, перегляд і експорт резюме.

## Файли
- Тип файлу визначається за вмістом (сигнатурою), а не за розширенням: «PDF», що насправді HTML, — відхиляється.
- Фото перекодовуються (sharp): видаляються EXIF/GPS і будь-яке вкладене «навантаження». SVG заборонено.
- З папки медіа віддаються лише файли, створені системою (`.webp/.jpg/.png/.mp4/.webm`), з `CSP: sandbox`.
- Резюме кандидатів лежать поза публічною папкою, видаються лише авторизованим HR, з `nosniff` і sandbox; кожне відкриття записується в журнал.
- Обмеження розміру: фото 25 МБ, відео 200 МБ, резюме 10 МБ.

## Форми й спам
- Невидиме поле-пастка (honeypot) — ботам відповідаємо «успіх», нічого не зберігаючи.
- Підписаний токен часу: форма, надіслана швидше ніж за 3 с або старша за 6 год, відхиляється; повторне використання токена — теж.
- 6 відправок / 15 хв з одного IP на кожну форму.
- Фільтр посилань і стоп-слів.
- Опційно — Cloudflare Turnstile (невидима капча).
- Валідація всіх полів на сервері, захист заголовків листів від інʼєкцій, IP зберігаються лише у вигляді хешу.

## Боти й навантаження
- Запити сканерів (`/wp-login.php`, `/.env`, `/.git`, `*.php`…) — миттєвий 404, повторні спроби → блокування IP на 1 годину.
- Загальний ліміт 300 запитів/хв з IP (+ ліміти в nginx), тайм-аути запитів, обмеження розміру тіла запиту.
- У Docker: користувач без root, файлова система лише для читання, без Linux-capabilities.

## Персональні дані
- Згода на обробку обовʼязкова у всіх формах, час згоди зберігається.
- HR може повністю видалити дані кандидата разом із резюме.
- Аналітика (GA4, Meta Pixel) вмикає cookies лише після згоди в банері (Google Consent Mode v2).

## Рекомендації для експлуатації
1. Працюйте лише через HTTPS (certbot), увімкніть Cloudflare.
2. Увімкніть 2FA для адміністраторів і HR.
3. Щоденний бекап (`scripts/backup.js`) + копія папки `data/backups` на інший сервер.
4. Раз на місяць: `npm audit` і оновлення (`git pull && docker compose up -d --build`).
5. Видаліть `data/INITIAL_ADMIN_PASSWORD.txt` після першого входу.
